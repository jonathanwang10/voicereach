# Phase 5: Voice and Audio Implementation Plan

> **For agentic workers:** Implement this plan task by task yourself, in order (no subagent-driven development). Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Move the app off expo-av, give the iOS audio session one owner, stream the
assistant's replies and the worker's microphone over the existing proxy, add barge-in,
replace regex RAG-lite with server-side read-only retrieval tools, auto-reconnect, and
add an offline assistant eval.

**Architecture:** The Record tab records field notes to an M4A file with `expo-audio`.
The Assistant uses `react-native-audio-api` for both directions: PCM16 24 kHz frames from
its `AudioRecorder` go out as `input_audio_buffer.append`, and `response.output_audio.delta`
chunks are played through an `AudioBufferQueueSourceNode` as they arrive.
`mobile/services/audioSession.ts` is the only code that changes the iOS audio session.
The backend proxy stays the security boundary: it declares four read-only tools in its
one `session.update`, runs them itself against Phase 4's `services/retrieval.py`, and sends
their results upstream as delimited `function_call_output` items. The client can never
send one.

**Tech Stack:** Expo SDK 53.0.27, React Native 0.79.6 (New Architecture on, Hermes),
`expo-audio` ~0.4.9, `react-native-audio-api` 0.13.6, FastAPI + `websockets`, OpenAI
Realtime GA (`gpt-realtime`), pytest, Jest (`jest-expo`).

**Spec:** `docs/superpowers/plans/2026-10-23-00-roadmap.md` (Phase 5; read Owner decision 3
and Global constraints first). Phase 5 depends on Phase 1 (`get_supabase`, `model_config`,
realtime session caps) and Phase 4 (`services/retrieval.py`).

## Review Focus

1. **The reply re-enters the microphone.** With full duplex on the loudspeaker, the
   assistant's own voice can trigger `input_audio_buffer.speech_started` and cut itself
   off. Expected: the reply plays to the end unless the worker speaks. Pinned by the
   `shouldSendMicFrame` tests (Task 8) and device check D5.7, whose fallback is
   `FULL_DUPLEX_MIC = false`.
2. **The worker taps stop mid-sentence.** Server VAD hasn't seen the end of speech, so
   no response would ever come. Expected: the question is still answered. Pinned by
   `stopping mid-speech commits the buffer and asks for a response` (Task 8).
3. **The Record tab starts while the Assistant listens or plays.** Expected: the Record
   tab wins, its recording is never paused, and the Assistant's mic and reply stop.
   Pinned by `a recording acquired during a conversation wins` (Task 2) and
   `a recording on the Record tab stops listening` (Task 8).
4. **The model sends malformed tool arguments** (a non-UUID id, `limit: 1000`, a missing
   query, broken JSON). Expected: a "no record" or clamped call, never an exception that
   ends the proxy. Pinned by the `parse_tool_arguments` tests and
   `test_get_person_with_a_non_uuid_id_does_not_query` (Task 5).
5. **The socket dies while the mic streams** (session time limit, network, background).
   Expected: the mic stops, the session is released, no frame is sent on a dead socket.
   Pinned by `no frames after the socket closes; the mic stops and the session is released`
   (Task 8).

## Library and API findings (verified 2026-10-23)

These were checked against npm, the Expo SDK 53 source (`expo/expo` branch `sdk-53`), the
react-native-audio-api docs and the OpenAI Realtime GA reference. Task 1 re-confirms them
against the installed type definitions before anything builds on them.

**expo-audio for SDK 53:** `mobile/node_modules/expo/bundledNativeModules.json` pins
`"expo-audio": "~0.4.9"` (expo-av is `~15.1.7`). From `packages/expo-audio/src` on `sdk-53`:

- Hooks: `useAudioRecorder(options: RecordingOptions, statusListener?: (s: RecordingStatus) => void): AudioRecorder`
  and `useAudioRecorderState(recorder: AudioRecorder, interval = 500): RecorderState`.
  The listener subscribes to the `'recordingStatusUpdate'` event (`RECORDING_STATUS_UPDATE`).
- Recorder: `prepareToRecordAsync(options?: Partial<RecordingOptions>): Promise<void>`,
  `record(): void`, `stop(): Promise<void>`, `uri: string | null`.
- `RecorderState`: `canRecord`, `isRecording`, `durationMillis`, `mediaServicesDidReset`,
  `metering?`, `url`. `RecordingStatus`: `id`, `isFinished`, `hasError`, `error`, `url`.
- `RecordingOptions`: `extension`, `sampleRate`, `numberOfChannels`, `bitRate`,
  `isMeteringEnabled?`, `android`, `ios` (`outputFormat?: IOSOutputFormat`,
  `audioQuality: AudioQuality`, ...), `web`. `AudioQuality.MEDIUM = 64`.
- Permissions: `requestRecordingPermissionsAsync(): Promise<PermissionResponse>` (`granted`, `status`).
- `setAudioModeAsync(mode: Partial<AudioMode>)` with `playsInSilentMode`, `allowsRecording`
  (iOS, default false), `interruptionMode: 'mixWithOthers' | 'doNotMix' | 'duckOthers'`,
  `interruptionModeAndroid`, `shouldPlayInBackground`, `shouldRouteThroughEarpiece` (Android).
  On iOS, `playsInSilentMode: true` gives category `.playAndRecord` when `allowsRecording`
  is true, else `.playback`; `.allowBluetooth` is added for play-and-record. **There is no
  `defaultToSpeaker`**, so expo-audio's record mode plays through the earpiece; that is why
  the Assistant's duplex mode is set through react-native-audio-api instead.
- Interruptions: expo-audio pauses a recording recorder when an interruption begins and
  may restart it when it ends with `shouldResume`. The recorder sees `isRecording` go false
  in between, which is what Task 3 detects.
- Config plugin: `["expo-audio", { "microphonePermission": "..." }]`.

**react-native-audio-api:** latest stable `0.13.6` (2026-09-23; `npm view react-native-audio-api dist-tags`).
Its RN compatibility page marks RN 0.79 "yes" on the New Architecture for 0.6.x to 0.13.x.
Peer deps: `react`, `react-native`, optional `react-native-worklets >= 0.7.0` (not needed here).

- `new AudioContext({ sampleRate: 24000 })`; `ctx.currentTime`, `ctx.destination`,
  `ctx.createBuffer(numOfChannels, length, sampleRate)`, `ctx.createBufferQueueSource(options?: { pitchCorrection: boolean })`,
  `ctx.decodePCMInBase64(base64, inputSampleRate, inputChannelCount, isInterleaved?)` (async; not used: ordering).
  `ctx.suspend()`, `ctx.resume()`, `ctx.close()`.
- `AudioBufferQueueSourceNode`: `enqueueBuffer(buffer): string` (a bufferId),
  `dequeueBuffer(id)`, `clearBuffers()`, `start(when?, offset?)`, `pause()`, `stop()`,
  `connect(ctx.destination)`, `onBufferEnded = ({ bufferId, isLastBufferInQueue }) => ...`.
- `AudioBuffer` follows Web Audio: `copyToChannel(Float32Array, channel)`, `getChannelData(channel)`.
- `AudioRecorder`: `new AudioRecorder()` (one instance preferred), `onAudioReady({ sampleRate, bufferLength, channelCount }, ({ buffer, numFrames, when }) => ...)`
  where `buffer` is an `AudioBuffer` of floats in [-1, 1], `clearOnAudioReady()`,
  `start(): Promise<...>`, `stop(): Promise<...>`, `isRecording()`, `onError(cb)`.
- `AudioManager.setAudioSessionOptions({ iosCategory, iosMode, iosOptions })` with
  `iosCategory: 'playAndRecord' | 'playback' | 'record' | ...`, `iosMode: 'default' | 'voiceChat' | 'spokenAudio' | ...`,
  `iosOptions: ('defaultToSpeaker' | 'allowBluetoothHFP' | 'allowBluetoothA2DP' | 'duckOthers' | 'mixWithOthers' | ...)[]`
  (there is no plain `allowBluetooth`); `AudioManager.setAudioSessionActivity(enabled): Promise<void>`;
  `AudioManager.requestRecordingPermissions(): Promise<'Undetermined' | 'Denied' | 'Granted'>`;
  `AudioManager.observeAudioInterruptions(true)`; `AudioManager.addSystemEventListener('interruption', ({ type: 'began' | 'ended', shouldResume }) => ...)`.
- Jest: the package ships `react-native-audio-api/mock`
  (`jest.mock('react-native-audio-api', () => require('react-native-audio-api/mock'))`).
- Config plugin: `["react-native-audio-api", { "iosBackgroundMode": false, "iosMicrophonePermission": "..." }]`
  (`iosBackgroundMode` defaults to **true**, which would add background audio; we turn it off).

**Fallbacks considered** (used only by the Task 1 decision rule):
- Capture: `@picovoice/react-native-voice-processor@1.2.3` (2026-04): `VoiceProcessor.instance`,
  `addFrameListener((frame: number[]) => ...)` (Int16 samples), `start(frameLength, sampleRate)`,
  `stop()`, `hasRecordAudioPermission()`; RN 0.68.7+, iOS 13+; New Architecture not stated (interop).
- Rejected: `react-native-live-audio-stream@1.1.1` (last published 2022-05, old architecture only).
- Last resort for both directions: `@speechmatics/expo-two-way-audio@0.1.2`, an Expo module with
  echo cancellation, but fixed at PCM16 **16 kHz** in and out, so it needs 24 kHz ↔ 16 kHz resampling.

**OpenAI Realtime GA event names used here** (developers.openai.com/api/reference/resources/realtime):
- Server: `input_audio_buffer.speech_started` (`audio_start_ms`, `item_id` of the user item to come),
  `input_audio_buffer.speech_stopped`, `conversation.item.input_audio_transcription.delta` /
  `.completed` (`item_id`, `content_index`, `transcript`) / `.failed`,
  `response.output_audio.delta` (`item_id`, `content_index`, `delta`, `response_id`),
  `response.output_audio_transcript.delta`, `response.output_audio.done`,
  `response.function_call_arguments.done` (`call_id`, `name`, `arguments` as a JSON string,
  `item_id`, `output_index`, `response_id`), `response.done` (`response.id`,
  `response.status` in `completed | cancelled | failed | incomplete`, `response.output[]`
  including `{type: "function_call", name, call_id, arguments}` items), `error`
  (`error.code`, `error.message`).
- Client: `response.cancel` (`response_id` optional), `conversation.item.truncate`
  (`item_id` of an assistant message, `content_index` "Set this to 0", `audio_end_ms`),
  `conversation.item.create` with `{type: "function_call_output", call_id, output: string}`,
  `response.create` (its `response` may carry `tool_choice: "none" | "auto" | "required"`).
- `session.update` (`session.type = "realtime"`): `tools: [{type: "function", name, description, parameters}]`,
  `tool_choice: "auto"`, `audio.input.transcription: {model, language}`
  (off by default; this plan sets `model` from `model_config.TRANSCRIBE_MODEL`), `audio.input.turn_detection: {type: "server_vad", threshold, prefix_padding_ms, silence_duration_ms, create_response, interrupt_response}`.
- OpenAI's function-calling guide reads the call from `response.done` and sends
  `response.create` after adding the output. Sending `response.create` while the response is
  still active is refused, so the proxy collects calls from `response.function_call_arguments.done`
  and runs them on that response's `response.done`.

## Deviations from roadmap

1. **`audioSession.ts` gets a fifth function, `acquireConversation(owner)`.** The four roadmap
   functions can't express "the mic streams while a reply plays", which barge-in needs.
   It sets duplex mode (play-and-record, `voiceChat`, `defaultToSpeaker`), returns null while
   a recording holds the session, and a Record-tab `acquireRecording` still wins over it.
   `acquirePlayback` and the other three keep the roadmap's exact signatures.
2. **C-24's speaker routing changes mechanism.** Replies reach the loudspeaker through
   `defaultToSpeaker` in duplex mode (or the `playback` category when not listening), not by
   turning recording off. Concretely: `audioSession.ts`'s conversation mode calls
   react-native-audio-api's `AudioManager.setAudioSessionOptions({ iosCategory: 'playAndRecord',
   iosMode: 'voiceChat', iosOptions: ['defaultToSpeaker', 'allowBluetoothHFP'] })` (Task 2), the JS
   wrapper over `AVAudioSession.setCategory(_:mode:options:)`. No config plugin is involved. If Task 1
   finds that API or the `'defaultToSpeaker'` option missing, its decision table's audio-route row
   applies (a small local Expo module).
3. **Tools run on `response.done`, not the moment `response.function_call_arguments.done`
   arrives** (see the OpenAI note above). The proxy still intercepts the `.done` event to
   collect the call. Added: at most `MAX_TOOL_ROUNDS = 3` tool rounds per question; the third
   round's `response.create` carries `tool_choice: "none"` so a looping model must answer.
4. **C-23 no longer applies to spoken questions.** The model hears the audio itself; the input
   transcript only fills the worker's bubble. A failed input transcription shows
   `[Couldn't transcribe]` in the bubble but the model may still answer.
5. **C-25's "text held until its audio has played" is replaced** by streaming the transcript
   as it arrives (roadmap 5.5). Per-item bubbles stay.
6. **`POST /api/voice-assistant/context` is removed** along with `context_service.py`: it only
   exposed the regex name detection the roadmap removes. Phase 1's assistant limits (1 s minimum,
   60 s maximum) disappear with `/api/voice-assistant/transcribe`.
7. **The input transcription model comes from config.** `audio.input.transcription.model` is
   `model_config.TRANSCRIBE_MODEL` (read at call time; default `gpt-transcribe` once
   Phase 3 lands, `whisper-1` before it), per Phase 1's "model names from config" rule, rather
   than a hardcoded string. Tests compare against `model_config.TRANSCRIBE_MODEL`, never a literal.
7a. **`REALTIME_MODEL` default becomes `gpt-realtime-2.1`** (`gpt-realtime` shuts down 2027-01-20;
   OpenAI's listed replacement). Task 5 changes the default in `services/model_config.py`, updates
   Phase 1's default-value test (`"gpt-realtime"` → `"gpt-realtime-2.1"` in both assertions), the
   README model line, and the manual-steps Environment variables row; the device checks run on it.
8. **"Taps" (roadmap 5.7) means the mic button.** While a reply plays, a mic tap interrupts it
   and leaves listening on; otherwise the tap toggles listening.
9. **Echo cancellation can't be verified offline.** Full duplex is the default; one constant,
   `FULL_DUPLEX_MIC` in `mobile/utils/assistantMessages.ts`, switches to half duplex (no frames
   sent while a reply plays; barge-in by tap only) if device check D5.7 fails.

    ```ts
      begin(itemId: string): void;                  // stops any other item (running its onDone); holds chunks until play()
      push(itemId: string, pcm: Uint8Array): void;  // ignored unless itemId is current; an odd byte carries to the next chunk

      end(itemId: string, onDone: () => void): void; // no more chunks; onDone once the last buffer has played (at once if none)

    }

    ```
    One `AudioContext({ sampleRate: 24000 })` created lazily; one `createBufferQueueSource()` per item,
    connected to `destination`; each chunk becomes `ctx.createBuffer(1, n, 24000)` + `copyToChannel(pcm16ToFloat32(...), 0)`.

    `endedMs` sums the durations of buffers whose `onBufferEnded` fired, `lastBoundary` is the
    `currentTime` of the last `onBufferEnded` (or of `start`), and `currentBufferMs` is the next
    queued buffer's duration (0 when none). Floor it.

Rules: when AppState becomes `active` and the socket is not open (and no connect is in flight), or
when a socket closes while `wasBackgroundedRef` is set (the close that iOS delivers right after
resume), schedule reconnect attempt 0. Each attempt runs `connect({ quiet: true })`: it does not
show the full-screen "Initializing" spinner and never clears `messages`; it does stop the reply and
the mic (`resetStreams`). A close or error during a quiet attempt schedules the next delay; after
the third failure the existing error card with Retry shows. A successful `onopen` resets the
attempt counter and clears `wasBackgroundedRef`. A refused handshake (`connectErrorMessage` gives
the 403 text) is never retried automatically. Retry and Clear cancel a pending timer. Timers are
cleared on unmount. Phase 1's caps still apply (a 1008 close counts as a failed try).

**Device id on the handshake.** Phase 1 keys the WebSocket connect limit and session cap on
`X-Device-Id` when present. If `mobile/services/deviceId.ts` exists (Phase 6 landed first), `connect()`
adds `'X-Device-Id': await getDeviceId()` beside `Authorization` in the handshake headers, with a
screen test asserting it. If it doesn't exist yet, Phase 6 Task 2 adds the header instead. Without it
the backend falls back to the user id.
